PRODUCT DECISIONS / Q&A 01 · 2026-10-28

为什么选择 Polygon，
而不是 Base、Tron 或以太坊？

关键不是“哪条链最好”，而是 Agent Lending 第一阶段需要哪种能力。按照原 PRD，先采用 Polygon PoS 作为低成本 EVM 存证与服务层候选；实际资金结算可以根据资金方、稳定币和安全要求选择其他链。

一句话结论：首期使用 Polygon PoS 的主要理由是 EVM 兼容、低成本与支付场景；但它不是继承以太坊完整安全性的 Rollup。若主要服务机构链上资产池，Base 值得平行评估；若资金方偏好 USDT-TRC20，可将 Tron 作为收付通道；高价值的最终锚定可考虑以太坊主网。
01 / 执行成本

大量业务事件成本可控

贷款与 Agent 可能产生频繁状态事件。低成本适合批次哈希、摘要与服务记录，但无需把每条聊天或个人资料写上链。

02 / 工程复用

Solidity / EVM 兼容

沿用 ERC-20、合约审计、索引、钱包和 EVM 开发工具。Base / 以太坊同样具备这些优势，不能只因此排除 Base。

03 / 支付生态

稳定币与企业收付基础

Polygon 已投入稳定币支付与法币出入金基础设施；但是否满足墨西哥 SPEI、托管、外汇和资金方需要，仍必须逐项验证。

建议 · 首期候选

Polygon PoS

小额、高频的摘要存证可优先评估 Polygon PoS，降低频繁合约操作的成本并沿用 EVM 开发工具。

  • 只写哈希和必要状态，不上链敏感贷款资料
  • 测试批量锚定、交易重试和确认阈值
  • 校验链上事件与链下 Loan Case 一致性

备选与注意事项

Base 同样支持低成本 EVM；若未来链上资金池集中在 Base，可以迁移或并行写入。

不可跳过的前置条件

真实资金方准入、KYC/AML、债权权属、支付授权、资产托管及风险审批必须在链下或受控系统中有效成立，不能因为“交易上链”就跳过。

推荐的渐进式多链架构

WhatsApp / H5 + A2A Agent用户申请 · 风控/合规 · 报价 · 合同 · 资金方授权
↓
统一 Loan Case & Ledger + Chain Adapter单一业务状态源 · 幂等键 · 对账 · 证据哈希 · Chain ID / Tx ID
↓
Polygon / Base存证、服务权益、资产池合约（经评审）
Tron可选 USDT-TRC20 收付通道
Ethereum高价值锚定或安全优先资产

跨链并不意味着同名代币天然互通。不同链上的 USDC / USDT、份额代币和合约地址必须分别记录，跨链转移需要独立的托管、消息与对账方案。

首期落地建议

阶段 1 · 不要求借款人持有钱包WhatsApp + MXN/SPEI；链下 Loan Case 为真实业务记录，链上只做合规允许的证明摘要。
阶段 2 · Polygon 与 Base 做双链 PoC分别验证合约费用、审计工具、稳定币结算、托管合作伙伴、风险阈值与退出流程。
阶段 3 · 按资金方增加支付通道资金方使用 TRC-20 时增加 Tron 适配；不要因为低手续费让核心贷款业务状态分裂。
阶段 4 · 资产池进入生产前再定主链根据真实资金、法务、托管和审计要求选择 Polygon / Base / Ethereum，不预设一定要跨链。
